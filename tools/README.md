# tools/

## new-client.js — підключення нового клієнта

Робить копію CRM під окремого клієнта і заливає її в новий репозиторій.

### Що робить

1. Збирає лише потрібні файли (10 шт.) — без бекапів, бота, документації
2. Підставляє назву, `client_slug` і ключі Supabase клієнта
3. **Вирізає панель `top_secret`** — клієнт її бачити не повинен
4. Створює репозиторій `gt-tires-app-<slug>` і заливає файли
5. Вмикає GitHub Pages

### Перед запуском

Клієнту потрібен **окремий проєкт Supabase** — не спільний із GT Tires.
Створюється на supabase.com, далі Settings → API: звідти беруться
`Project URL` і `anon public` ключ.

### Запуск

```bash
export GITHUB_TOKEN='ghp_...'

# спершу перевірка, нічого не заливається
node tools/new-client.js --dry \
  --name "Шиномонтаж Колесо" \
  --slug koleso-brovary \
  --supabase-url https://xxxxxxxx.supabase.co \
  --supabase-key eyJ...

# якщо все ок — прибрати --dry
```

Токен після роботи видалити: github.com/settings/tokens

### Після запуску

1. Відкрити `licenses.html` → «Підключити»
2. `client_slug` вписати той самий, що передавали скрипту
3. Скинути клієнту посилання, яке надрукував скрипт

Без кроку 1 клієнт побачить екран «Доступ призупинено» — ліцензії ще немає.

### Захист від помилок

Скрипт відмовиться працювати, якщо:

- у `--supabase-url` вказано базу GT Tires (клієнт побачив би чужі дані)
- slug не латиницею або з пробілами
- ключ не схожий на anon-ключ
- у зібраному файлі лишилась згадка адмінки

### Оновлення наявного клієнта

Той самий запуск із тим самим `--slug`. Файли перезапишуться,
дані клієнта в його Supabase не постраждають.

### Перевірка

`npm --prefix tests run test:client` — 21 перевірка, серед них те,
що клієнту не витікає панель адміністратора, пароль і чужа база.
